# Floorpy

![Floorpy Logo](floorpy.png)

**A portable Floorp browser package for Windows repair, recovery, and IT toolkits.**

[Floorp](https://floorp.app/) is a browser built on Firefox. Floorpy packages its Windows application files into a single executable, `floorpy.exe`. Build it on Windows, copy it to a USB drive or recovery image, and launch the packaged browser without installing Floorp on each machine.

The build script downloads or reuses Floorp's Windows x64 application files, compresses them with 7-Zip, and wraps them in a self-extracting executable. The package carries the browser files with it, so it can be prepared in advance and taken to another machine.

## Why it is useful

- **WinPE and recovery environments:** Carry a browser for reading repair instructions, downloading drivers, or accessing web-based management tools while working on a machine outside its installed Windows system. Test the package with your WinPE image; browser compatibility depends on the components and networking available in that image.
- **Diagnostic USB drives:** Keep one executable alongside your other repair tools instead of installing a browser on every machine you service.
- **A prepared starting profile:** Package browser settings in `floorp/TempProfile` so each fresh extraction starts with the same configuration.
- **Offline preparation and distribution:** Build from an existing local Floorp folder without internet access. The finished package includes its browser payload; visiting websites still requires a connection.

## Floorpy, Nomad, and the Firefox comparison installer

This repository also includes two separate executables in [`other/`](other/):

| File | Purpose | How it gets the browser |
| --- | --- | --- |
| `floorpy.exe` (generated by `Build.bat`) | A portable package you can build once and carry between machines. | Contains the Floorp files selected at build time. Rebuild it when you want to refresh that copy. |
| [`other/Nomad-Floorp.exe`](other/Nomad-Floorp.exe) | An alternative launcher that downloads fresh Floorp builds itself. | Fetches Floorp through its own download workflow, which requires internet access. |
| [`other/Firefox_Nightly_Installer.en-US.exe`](other/Firefox_Nightly_Installer.en-US.exe) | Included for comparison with default Firefox behavior, appearance, and website compatibility. | Use the Firefox Nightly installer separately to set up the comparison browser. |

Use Floorpy when you want a package containing a known browser build, ready to copy and run. Use `Nomad-Floorp.exe` when you want the launcher to obtain fresh Floorp builds for you. Both executables in `other/` are independent of the Floorpy build process.

The Firefox comparison installer uses [Mozilla's Nightly development channel](https://www.mozilla.org/en-US/firefox/channel/desktop/#nightly). Account for differences in browser version and release channel when comparing its results with Floorp or stable Firefox.

## Build your first package

Use a Windows x64 machine and extract or clone this repository into a writable folder. Keep these included files beside `Build.bat`:

| File | Role |
| --- | --- |
| `7za64.exe` | Compresses the browser files and extracts the downloaded installer. |
| `7zS264.sfx` | Supplies the self-extracting executable module. |
| `ResourceHacker.exe` | Applies the icon and execution manifest. |
| `icon.ico` | Icon for the finished executable. |
| `Manifest.txt` | Requests execution with the current user's privileges (`asInvoker`). |
| `run.bat` | Launches the extracted browser and handles temporary-folder cleanup. |

The download options also require Windows PowerShell and internet access. The script tries `curl.exe` first when available, then falls back to PowerShell for the transfer.

1. Open `Build.bat`, or run it from PowerShell in the repository folder:

   ```powershell
   .\Build.bat
   ```

2. Press **U** to download the latest Windows x64 Floorp release and build the complete package.
3. Wait for **Build completed successfully.** The result is `floorpy.exe` in the repository root.
4. Copy `floorpy.exe` to your toolkit or target environment and run it.

Downloading uses the [official Floorp GitHub releases](https://github.com/Floorp-Projects/Floorp/releases). When an existing `floorp/` folder is replaced, the script keeps it as `floorp.previous/`, replacing any older backup at that location.

### Build menu

| Key | Action |
| --- | --- |
| **1** | Download the latest Windows x64 Floorp release into `floorp/`. |
| **2** | Pack `floorp/` and `run.bat` into `floorp.7z`. |
| **3** | Combine `floorp.7z` with the SFX module to create `floorpy.exe`. |
| **4** | Apply the custom icon and manifest to `floorpy.exe`. |
| **F** | Build from the current local `floorp/` folder: pack, create the executable, and apply resources. |
| **U** | Download Floorp, then perform the complete build. |
| **Q** | Quit. |

Each numbered option performs one step. **F** and **U** run the complete build sequence and stop if a step fails. The current script packages the application files as supplied; it has no debloat step.

### Build offline or customize the profile

For an offline build, supply the full extracted Floorp application folder as `floorp/`, with `floorp/floorp.exe` present, then choose **F**. All required build tools must also be available locally.

For a prepared profile, place its files directly in `floorp/TempProfile` before building. A root-level `TempProfile/` folder is not copied into the browser folder automatically.

To customize a fresh download, choose **1**, prepare `floorp/TempProfile`, then choose **F**. Choosing **U** downloads a replacement `floorp/` folder, so make profile changes after downloading and before packing.

### Unattended builds and GitHub Actions

The same complete build operations are available without menu prompts or pauses:

```powershell
.\Build.bat --update
.\Build.bat --local
```

`--update` downloads Floorp and builds the package, while `--local` builds from the existing `floorp/` folder. Both return exit code `0` on success and `1` on a build failure; unsupported arguments return `2`.

The [Build Floorpy workflow](.github/workflows/build.yml) checks the latest stable Floorp release on pushes to `main`, on manual runs, and hourly at minute 23 UTC. Once the workflow is on the default branch, it handles publishing automatically:

1. On the first run, it builds the current Floorp release and publishes a matching Floorpy release, such as `floorpy-v12.21.2`.
2. Later checks compare that version's release with the existing Floorpy release. If all release files are already published, the Windows build is skipped.
3. When Floorp publishes a new stable version, the next check downloads that exact version, verifies its upstream SHA-256 digest, runs the regression checks, builds Floorpy, and verifies the packaged archive before publishing.

Each [GitHub release](https://github.com/skonester/floorpy/releases) includes `floorpy.exe`, `floorpy.exe.sha256`, this README, and the repository license. The newest published package is marked as the latest release. Failed or incomplete uploads can be retried by running the workflow again.

To start a check immediately, open **Actions > Build Floorpy > Run workflow** and select the default branch. Publishing uses GitHub's provided `GITHUB_TOKEN`; no additional secrets are required. Write permission is granted only to the publishing job. Complete releases are left in place, so repeating a check for the same Floorp version does not replace its files.

Pull requests and manual runs from other branches build test artifacts without publishing a release. Download **floorpy-windows-x64** from the successful build's **Artifacts** section; these artifacts contain the same four files and are retained for 30 days.

Scheduled checks use the workflow on the default branch. GitHub may delay scheduled runs and disables schedules in public repositories after 60 days without repository activity; see [GitHub's schedule documentation](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule) if automatic checks stop.

## Run the finished package

The self-extracting package unpacks the browser and starts `run.bat`. The launcher runs Floorp with the `TempProfile` profile inside the extracted browser folder.

Leave the launcher console open while browsing. After Floorp closes, the launcher waits for the profile lock to be released and attempts to remove the extracted folder. Cleanup is restricted to a validated folder beneath `%TEMP%`; it skips `%TEMP%` itself, folders outside it, and paths containing junctions or symbolic links between the extraction folder and the temporary root.

Profile changes are temporary when the extracted folder is cleaned up. Save files you want to keep outside that folder. If you manually extract and run the files elsewhere, the launcher leaves that folder in place.

The finished `floorpy.exe` contains the browser version used during its build. To distribute a newer version, run **U** again and replace the copies in your toolkit or recovery image.

## Repository files and generated output

| Path | Contents |
| --- | --- |
| `Build.bat` | Interactive download and packaging script. |
| `run.bat` | Browser launcher included in the generated package. |
| `other/` | Nomad Floorp launcher and the Firefox Nightly comparison installer. |
| `floorp/` | Local browser files used as build input; created by the download step or supplied manually. |
| `floorp.7z` | Compressed browser payload generated during packing. |
| `floorpy.exe` | Finished portable browser package. |
| `.build/` | Downloaded installer and extraction workspace. |
| `floorp.previous/` | Backup from the previous browser download. |
| `ResourceHackerScript.txt` | Legacy standalone resource-editing helper. `Build.bat` applies resources directly. |
| `tests/` | Regression checks for the Windows batch scripts and release automation. |
| `scripts/floorp_release.py` | Checks upstream versions and prepares a version-pinned, checksum-verified Floorp payload for CI. |

`floorp.7z`, `floorpy.exe`, `.build/`, and `floorp.previous/` are ignored by Git. The local `floorp/` input folder is not currently ignored; check your changes before committing browser files or a prepared profile.

## Development checks

With Python installed on Windows, run:

```powershell
python -B -m unittest discover -s tests -v
```

The checks use stubbed build operations and disposable folders to exercise menu failures, path validation, cleanup, release detection, and installer verification. They do not download or launch a browser or publish releases.
